| CKV_AWS_144 (no cross-region replication) | secure-bucket module | Single-region lab | Multi-region version |
| CKV2_AWS_62 (no event notifications) | secure-bucket module | Not needed for log storage | Never |
| NACL ingress rule 110: TCP 32768–65535 from 0.0.0.0/0 | modules/network | Return traffic for connections the subnets start (e.g. S3 via the gateway endpoint). NACLs are stateless and can't use prefix lists. No internet gateway or NAT, so nothing on the internet can reach these subnets | If an internet gateway or NAT is ever added |
| NACL egress: allow all | modules/network | No route to the internet exists; the only way out is the S3 endpoint, which its own policy restricts | If an internet gateway or NAT is ever added |
| S3 endpoint policy uses Principal "*" | modules/network | Endpoint policies are written with Principal "*". The aws:ResourceAccount condition limits it to buckets this account owns | Never |
| S3 endpoint blocks AWS-owned buckets (side effect) | modules/network | Deliberate: no workloads run in these subnets. EC2/ECS here would need an allow-list for dnf repos, ECR layers and SSM buckets | If EC2 or ECS is added |
| CKV_AWS_356 ("*" as resource) | modules/iam: boundary | Read-only Get/List/Describe; most can't be resource-scoped. Only writes: the state lock file under state_key_prefix. Denies (tampering, identity creation, IAM escalation) are defence-in-depth, since the Allows are read-only today | Narrow wildcards to the calls CloudTrail shows after the first CI plan |
| CKV_AWS_356 ("*" as resource) | modules/iam: ci_plan | Same read list, needed for terraform plan to refresh the baseline. Writes limited to the lock file only; CI can't modify or delete state | Same as above |
| Design note | modules/iam: auditor | Auditor uses AWS SecurityAudit as both its policy and its boundary: full read-only security view, no writes possible. Requires MFA within the last hour | None |
| Design note: shared CI role | modules/iam: ci_plan | PR and main runs share one role with DeleteObject on *.tflock, so a PR could force-unlock a main run. Worst case is a forced unlock, not state corruption; CI only plans | When an apply role is added: separate role for PR plans, or PR plans with -lock=false |
| Design note: blanket Deny on iam:CreateRole / iam:PassRole | modules/iam: boundary | Right for a plan-only role. A future apply role under this boundary couldn't create or pass the flow-logs service role | When an apply role is added: Deny CreateRole unless iam:PermissionsBoundary equals this boundary's ARN; scope PassRole with iam:PassedToService |
|CKV_AWS_35 / Trivy AWS-0015 (trail not KMS-encrypted) | modules/foundation: aws_cloudtrail.main | Logs land in a private, TLS-only, versioned bucket with SSE-S3. A KMS key costs $1/month plus requests | Roadmap: KMS CMK |
| CKV_AWS_252 (no SNS topic on the trail) | modules/foundation: aws_cloudtrail.main | Alerting is done by modules/detection (EventBridge rules plus the IAM CloudWatch alarm), not the trail's SNS file-delivery notices | If detection is ever removed |
| CKV_AWS_158 / Trivy AWS-0017 | modules/foundation: aws_cloudwatch_log_group.trail | CloudWatch Logs encrypts at rest by default; a CMK adds cost | Roadmap: KMS CMK |
| CKV_AWS_338 (log retention under 1 year) | modules/foundation: aws_cloudwatch_log_group.trail | 7 days keeps it in the free tier; it only feeds the IAM alarm. The full record is the S3 copy of the trail | If CloudWatch becomes the record of truth |
| CCKV_AWS_9 / Trivy AWS-0062 | modules/foundation: aws_iam_account_password_policy | Follows NIST SP 800-63B and current CIS: no forced rotation; 14+ characters, MFA and reuse prevention instead | Never |
| Design note: once-per-account resources | modules/foundation | GuardDuty detector, EBS default encryption (per Region), account S3 Block Public Access and password policy (per account) can exist only once; apply this module once per account. The trail covers all Regions; GuardDuty, Access Analyzer and EBS encryption cover us-east-1 only, deliberately for a single-Region lab | Multi-account: move to Organizations with delegated admin |
| Design note: CloudTrail log role trusts by account, not by trail ARN | modules/foundation: trail_to_logs_trust | aws:SourceAccount limits the role to this account, and the role can only write to one log group. AWS doesn't document whether CloudTrail sends aws:SourceArn when it assumes this role, so an ARN condition could break trail creation | After first deploy: add the aws:SourceArn condition, apply, and keep it if the trail still delivers to CloudWatch Logs |
| CKV_AWS_26 / Trivy AWS-0095 (SNS topic not encrypted) | modules/detection: aws_sns_topic.alerts | The AWS-managed SNS key can't grant EventBridge or CloudWatch alarms permission to publish, so using it would silently stop every alert. Messages are alert metadata, not secrets | Roadmap: KMS CMK whose key policy allows events.amazonaws.com and cloudwatch.amazonaws.com |
| Design note: all GuardDuty severities alert | modules/detection | Lab needs every finding, including Low ones such as CloudTrailLoggingDisabled from Attack B. Inbox noise is acceptable for 2 days | Production: filter severity >= 4 and route Low findings to a daily digest |
| CKV2_AWS_3 (GuardDuty not org-managed) | modules/foundation: aws_guardduty_detector.this | Single standalone account with no AWS Organizations. GuardDuty is enabled directly in us-east-1 | Multi-account: Organizations with GuardDuty delegated admin and auto-enable |
| Design note: force_destroy on the CloudTrail/flow-log bucket | envs/dev: module.logs | Lab is torn down the same day; force_destroy lets teardown remove versioned log objects. Evidence is exported to docs/evidence first | Production: no force_destroy; add S3 Object Lock for audit logs (roadmap) |
| Design note: PR plans run branch code with AWS credentials | .github/workflows + modules/iam | Anyone who can push a branch could run code (e.g. data "external") while holding ci-plan. The role is read-only plus the state lock file, and fork PRs get no token | If collaborators are added: require approval for workflow runs, or run PR plans without credentials |
